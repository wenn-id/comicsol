# Comic Sol v2.0.0rc6

> **Draft — not published.** This tag does not exist yet. The artifacts described below are
> produced by `.github/workflows/release.yml` when `v2.0.0rc6` is pushed, and the release
> qualification gate has not been run. Nothing here is a claim that a download exists.

`v2.0.0rc6` is a **prerelease** carrying three complete milestones — 28 issues — none of which
had shipped before. It re-cuts the candidate that `v2.0.0rc5` was prepared for, at the exact
`main` commit reviewed after that tag's Native Release failed, because an immutable release tag
that failed to publish is never moved or reused.

It is not a stable release. `docs/releases/v2.0-stable-criteria.md` remains the authoritative
gate for a stable `2.0.0` tag, and it is not yet satisfied: the criteria require per-platform
qualification from the release artifacts themselves and a recorded maintainer decision.

## Versioning decision: v2.2 is a milestone, not a package version

This candidate records the versioning strategy required before publishing, so there is no
ambiguity about what "v2.2" means:

- **`v2.0`, `v2.1`, and `v2.2` are milestone names — planning labels, not version tags.** They
  describe *what* was built (Stability, Reliability & DX, Comic Quality), not the distribution
  version that carries it. `docs/releases/milestone-delivery.md` is the authority for that
  mapping.
- **The package version is `2.0.0rc6`.** `comic_sol_product/version.py`, the Compose image tag,
  package metadata, native archive and SBOM names, this document, `CHANGELOG.md`, and the
  candidate installer fixtures all agree on it. Published-install examples in `docs/install.md`
  intentionally remain on `2.0.0rc4`, the latest available prerelease, until `2.0.0rc6` is
  published. Once built, every candidate artifact must report `comic-sol 2.0.0rc6` from
  `comic-sol --version`.
- **No `2.2.0` distribution exists and none is planned by this candidate.** The v2.2 milestone
  ships inside the `2.0.0rc6` prerelease, exactly as v2.0 and v2.1 do.

### Why a new candidate instead of reusing `v2.0.0rc5`

The annotated `v2.0.0rc5` tag was prepared but its Native Release runs failed, so no GitHub
Release, archive, checksum, SBOM, or signature was ever published for it. `main` then advanced
two release fixes past the tag's target. Moving or re-pointing an immutable release tag would
break the guarantee that a tag always names the exact bytes that were reviewed, so `v2.0.0rc5`
is left where it is and this candidate is cut fresh. `v2.0.0rc6` will be annotated at the
reviewed `main` commit after this PR lands; the older tag is neither moved nor deleted.

## Why the v2.0 milestone appears here

The four earlier `2.0.0rc*` prereleases shipped the v2.0 product line on 2026-07-29/30. The
v2.0 **milestone** — the work that hardened and qualified it — merged on 2026-08-18/19, after
`2.0.0rc4` was published. It therefore ships here, not there. `docs/releases/milestone-delivery.md`
records the merge window of each milestone against the publish date of each tag.

## Added — v2.0 milestone (Stability)

- The authoritative stable release gate at `docs/releases/v2.0-stable-criteria.md`, verified as
  present by the release workflow so it cannot be removed and released around.
- Golden end-to-end pipeline coverage over a committed project, a lifecycle failure-injection
  suite, and clean-install verification across the supported platforms.
- `resume` is read-only and idempotent after a recovery; a second resume previously failed with
  `resume requires a BLOCKED project`, which made recovery a one-shot operation.
- A structured `doctor` report with stable check IDs, `pass`/`warn`/`fail` status, messages, and
  remediation, exposed identically through the CLI and MCP while the legacy fields remain.
- The `comic_sol_product.errors` registry of canonical `CS-*` codes, surfaced in CLI JSON and
  MCP error envelopes, with append-only allocation documented in `docs/structured-errors.md`.
- An explicit project schema compatibility contract: unsupported versions are refused with
  `UnsupportedSchemaVersionError`, and migration is permitted only through a registered hook
  published inside the journal-backed project transaction.
- A release qualification gate as a workflow rather than a checklist someone remembers to run.

## Added — v2.1 milestone (Reliability & DX)

- The benchmark framework, a nine-project real-world corpus, a character consistency benchmark,
  and version-tagged benchmark summaries that fail closed on records from a foreign harness.
- Stage-aware CLI progress on `stderr`, leaving `stdout` and the `--json` envelope untouched.
- A first-run onboarding path at `docs/onboarding.md`.
- Official example projects with explicit evidence tiers and an on-demand builder that adds no
  tracked binaries.
- `AGENTS.md`, a development constitution whose eight articles each point at a gate that exists.

## Added — v2.2 milestone (Comic Quality)

- The Character Identity Pack: one derived, byte-reproducible artifact that panel prompts embed
  instead of paraphrasing the character bible per panel.
- A shot-aware reference strategy that publishes every selection and omission with its reason.
- Per-trait character-consistency QA, and selective panel repair that no longer re-rolls an
  accepted panel to fix a localized defect.
- Deterministic speech balloon placement QA, verifiable multi-character dialogue attribution,
  and an inventoried typography coverage policy with optional per-script font extensions.
- SFX render modes with recorded provenance, deterministic verification flags, and a supported
  repair path that archives the rejected rasters.

## Quality and evidence

This prerelease retains deterministic normalization, typography preflight, the immutable
`four-grid` layout, artifact-bound page QA, full-content PDF verification, and the deterministic
quality matrix. Matrix and benchmark evidence prove mechanics only and are not a substitute for
visual review; deterministic benchmark runs label themselves `proves_visual_quality: false`.
The separate [v2.2 live visual evidence gate](v2.2-live-visual-evidence.md) defines the required
provider/model/reviewer provenance, before/after renders, complete character scorecard, defect
ledger, limitations, and reviewer-approved promotion threshold. Its current status is
**BLOCKED** because no real-provider bundle has been published; this draft must not describe the
candidate as visually qualified until that evidence passes.

## Distribution

The native archive matrix is Linux x86_64, macOS arm64, and Windows x86_64.
WSL2 uses the Linux x86_64 archive; it has no separate native archive. Source installation
supports Linux, macOS, Windows, and WSL2 on Python 3.11+. Intel macOS is
source-install-only; it has no native archive.

The exact native payload names are:

| Target | Archive | Metadata | SBOM |
|---|---|---|---|
| Linux x86_64 | `comic-sol-2.0.0rc6-linux-x86_64.zip` | `comic-sol-2.0.0rc6-linux-x86_64.metadata.json` | `comic-sol-2.0.0rc6-linux-x86_64.sbom.json` |
| macOS arm64 | `comic-sol-2.0.0rc6-macos-arm64.zip` | `comic-sol-2.0.0rc6-macos-arm64.metadata.json` | `comic-sol-2.0.0rc6-macos-arm64.sbom.json` |
| Windows x86_64 | `comic-sol-2.0.0rc6-windows-x86_64.zip` | `comic-sol-2.0.0rc6-windows-x86_64.metadata.json` | `comic-sol-2.0.0rc6-windows-x86_64.sbom.json` |

The prerelease will also include:

- Python wheel and source archive
- transactional POSIX and PowerShell installers
- SHA-256 checksums
- CycloneDX 1.6 SBOMs generated from each native build environment, each bound to the exact
  archive in the table above
- keyless Sigstore bundle `SHA256SUMS.sigstore.json` for the global checksum manifest
- non-root OCI build definition

Native archives use keyless Sigstore verification but are not Authenticode-signed or
Apple-notarized. Verify `SHA256SUMS.sigstore.json` and then the archive digest in `SHA256SUMS`
before use.
