# v2.2 live visual and character-consistency evidence

## Current status: BLOCKED — live bundle not published

The deterministic v2.2 benchmark remains useful evidence for pipeline, export, resume,
acceptance, and dialogue mechanics. It is not evidence of artistic quality. The committed
`baseline-v2.0.0rc6.json` therefore remains correctly unscored at `0/105` visual dimensions.

No provider credential or real retained-raster bundle is available in this repository, and the
engine is forbidden from calling an image provider. This document does **not** convert the
structural baseline into a visual pass or invent reviewer decisions. Promotion remains blocked
until an authorized agent session runs the fixed benchmark with a real provider and publishes
the sanitized bundle described below.

`scripts/live_visual_evidence.py` is the fail-closed publication gate for that bundle. It reads
local files only, verifies decodable PNGs and their SHA-256 bindings, rejects unknown manifest
fields and Markdown/control injection, and emits machine-readable plus Markdown summaries only
when every requirement passes. Candidate identity and reviewer attestation are supplied
independently on the command line so the manifest cannot approve itself.

## Promotion threshold

A reviewer may approve the candidate only when all of these conditions hold:

- The manifest candidate matches the independently supplied 40-character commit and engine
  version, and its reviewer-attestation digest matches the independently supplied SHA-256.
- Evidence mode is `live-visual`, with sanitized provider/model identity, reviewer identity,
  review method, timezone-qualified review timestamp, and explicit `approved` decision.
- Character identity coverage is **105/105** across both characters, all seven dimensions,
  five views, nine expressions, four lighting conditions, and four scenes.
- Overall character identity is at least **3.5/4**.
- Every character, dimension, view, expression, lighting, and scene aggregate is at least
  **3.0/4**, and no individual score is below **3/4**.
- Every v2.2 material quality change (`CS-019` through `CS-026`, plus `CS-034` and
  `CS-035`) has its own hash-bound, decodable PNG before/after pair and a reviewer decision of `improved` or `accepted-no-regression`.
- The reviewer records character identity, anatomy, action, composition, continuity,
  text-free generation, SFX, lettering, and technical raster quality. A category may pass or
  carry an explicitly accepted warning; it may not fail.
- Every canonical panel has exactly one accepted, decodable retained raster bound into the
  scorecard; rejected attempts, repairs, and retries
  are linked by stable IDs. Error-severity defects must be repaired; accepted warnings require
  a separate rationale and reviewer decision.
- At least one honest limitation is published that explicitly names the provider, model, and
  reviewer scope. A single-provider, single-model, single-reviewer run must never be presented
  as universal quality evidence.

These thresholds apply to promotion evidence only. They do not make subjective scores part of
the provider-free pull-request benchmark, and they do not weaken any deterministic gate.

## Bundle layout and safe provenance

The operator creates a private working directory, then publishes only the reviewed subset:

```text
visual-evidence/
├── manifest.json
├── reviewer-attestation.json
├── scorecard.json
├── attempts/
│   └── <panel>-<sequence>.png
└── renders/
    ├── <change>-before.png
    └── <change>-after.png
```

`manifest.json` uses `kind: "milestone-live-visual-evidence"` and `schema_version: "1.0"`.
Every referenced file is a contained POSIX-relative path paired with its lowercase SHA-256.
The manifest contains summaries, observations, repair decisions, and limitations; it must not
contain raw prompts, provider responses, credentials, tokens, endpoints, or account IDs.

A minimal shape is shown below. The real manifest must include every canonical aggregate and
all nine quality-review categories; placeholders cannot pass validation.

## Authorized live-run procedure

1. Record the exact candidate commit and materialize the unchanged benchmark:

   ```bash
   python -m tests.consistency_benchmark materialize /tmp/comic-sol-consistency
   ```

2. In an authorized agent session, render every `prompts/panels/*.txt` with one real image
   capability. Keep provider, model, references, and fixed inputs constant. The engine must not
   receive credentials or call the provider itself.
3. Retain each initial and retry raster outside the repository. Fill all 105 scorecard entries.
   Review all required quality categories and record every defect, repair, retry, warning, and
   decision. Do not delete rejected attempts before their hashes are recorded.
4. Select a representative before/after pair for every material quality change. A change with
   no visible effect still needs a reviewed `accepted-no-regression` pair; prose is not a render.
5. Copy only the publishable evidence subset into one bundle, calculate SHA-256 digests, remove
   raw prompts/provider payloads, and state the limitations.
6. Validate and render the public scorecard:

   ```bash
   python scripts/live_visual_evidence.py \
     --manifest visual-evidence/manifest.json \
     --expected-commit "$CANDIDATE_SHA" \
     --expected-engine-version "$CANDIDATE_VERSION" \
     --expected-reviewer-attestation-sha256 "$REVIEWER_ATTESTATION_SHA256" \
     --json-output visual-evidence/published/summary.json \
     --markdown-output visual-evidence/published/summary.md
   ```

7. Publish the before/after renders, scorecard, generated summaries, and limitations with the
   exact candidate's release evidence. A non-zero validator exit, missing live bundle, candidate
   mismatch, or absent reviewer approval means **BLOCKED**, not “mechanically green.”

## Known limitations

Even a passing bundle measures one fixed story, provider/model combination, reference set, and
review session. It does not prove quality for every art style, language, provider, stochastic
seed, or future provider revision. Provider identity is descriptive provenance rather than a
reproducibility guarantee. Human review remains subjective, so the public scorecard must retain
its reviewer and method rather than presenting the numbers as objective ground truth.
